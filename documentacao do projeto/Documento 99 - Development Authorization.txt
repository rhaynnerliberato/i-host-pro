──────────────────────────────────────────────
OBJETIVO
──────────────────────────────────────────────

Seu objetivo é desenvolver completamente o sistema iHostPro.

O desenvolvimento deverá ser incremental, consistente, rastreável e sustentável.

Você possui autonomia apenas para decisões técnicas permitidas pela Decision Making Policy.

Sempre preserve exatamente o comportamento definido pela documentação.

──────────────────────────────────────────────
PLANEJAMENTO
──────────────────────────────────────────────

Antes de escrever qualquer linha de código:

1. Analise a documentação obrigatória.
2. Identifique todos os módulos do sistema.
3. Identifique dependências entre eles.
4. Organize um plano de desenvolvimento dividido em fases.
5. Ordene as fases pela dependência técnica.
6. Apresente esse plano para aprovação.

Após aprovação:

- desenvolva apenas uma fase por vez;
- conclua completamente uma fase antes de iniciar a próxima;
- siga rigorosamente a Definition of Done.

Ao finalizar cada fase:

- apresente um relatório;
- aguarde autorização para iniciar a próxima.

Nunca implemente múltiplas fases simultaneamente.

──────────────────────────────────────────────
FORMA DE TRABALHO
──────────────────────────────────────────────

Antes de iniciar qualquer tarefa:

- compreenda completamente a documentação relevante;
- identifique os módulos afetados;
- identifique dependências;
- identifique riscos;
- verifique ADRs relacionadas;
- analise cuidadosamente o código existente.

Depois disso:

implemente apenas o escopo aprovado.

Ao concluir:

- atualize documentação quando necessário;
- atualize testes;
- mantenha consistência arquitetural;
- valide a Definition of Done.

──────────────────────────────────────────────
CONTINUIDADE DO PROJETO
──────────────────────────────────────────────

Este projeto é permanente.

Cada implementação deverá preservar integralmente sua continuidade.

Sempre que uma alteração for solicitada:

- compreenda primeiro a implementação existente;
- preserve toda funcionalidade não relacionada;
- identifique exatamente os arquivos afetados;
- realize apenas alterações pontuais;
- modifique apenas o necessário;
- preserve compatibilidade;
- preserve arquitetura;
- preserve documentação;
- preserve testes existentes.

Nunca reescreva módulos inteiros apenas porque encontrou uma solução melhor.

Nunca recrie arquivos completos quando pequenas alterações forem suficientes.

Nunca regenere grandes partes do projeto para implementar pequenas mudanças.

Nunca substitua código funcional apenas por preferência técnica.

Sempre prefira:

- alterações pequenas;
- alterações localizadas;
- menor impacto possível;
- menor quantidade possível de arquivos modificados;
- máxima preservação da implementação existente.

O projeto deverá evoluir continuamente.

Nunca deverá ser reconstruído.

──────────────────────────────────────────────

Sempre prefira soluções previsíveis, simples e fáceis de manter.
