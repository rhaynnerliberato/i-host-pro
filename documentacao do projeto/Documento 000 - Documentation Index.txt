# 1. Purpose

This document is the entry point for all project documentation.

Its purpose is to help every AI agent identify:

- which document should be consulted;
- when it must be consulted;
- which document is authoritative for each subject;
- which documents are optional depending on the requested task.

This document shall always be read before any development activity.

---

# 2. Documentation Hierarchy

Project documentation follows the hierarchy defined by the Engineering Constitution.

When multiple documents discuss the same subject, the most specific document is authoritative for that subject.

# 6. Documentation Lifecycle

Documentation shall evolve together with implementation.

Whenever implementation changes:

- architecture;
- business rules;
- workflows;
- entities;
- APIs;
- integrations;
- infrastructure;

the corresponding documentation shall also be updated.

Implementation is not considered complete until documentation is synchronized.

---

# 7. Missing Documentation

If implementation depends on documentation that does not exist:

1. identify the missing subject;
2. determine whether an existing document should be extended;
3. recommend creating new documentation only when necessary.

Avoid duplicate documents.

---

# 8. Final Principle

Documentation is the authoritative description of the project.

Source code is the implementation of that documentation.

Whenever uncertainty exists, consult the appropriate document before making implementation decisions.
